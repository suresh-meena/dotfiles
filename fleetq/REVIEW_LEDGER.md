## How to read this ledger

KEEP preserves the requirement; AMEND/REPLACE corrects or completes it; VERIFY means the file asserts a local fact for which no independent host/repository evidence was supplied; DEFER retains a feature behind a defined release gate. STRUCTURE marks formatting rather than a behavioral requirement. Mixed dispositions distinguish a sound requirement from an unsupported implementation claim. Research IDs resolve in the refined plan's primary-source registry.

No production host was contacted. No implementation test, source-code inspection of the named private repositories, or live hardware verification is claimed. This ledger is an editorial/design audit, not a test report.

## Release-blocking findings

The original plan requires material changes before implementation: ambiguous Slurm submission is not deduplicated by name; terminal/retryable LOST conflicts with possible remote execution; global budgets cannot be implemented with independent host-local files; `--collect` may erase terminal service metadata; cgroup memory enforcement cannot be replaced by RSS warnings; short idle samples and visibility variables do not establish exclusive GPU ownership; spooling a script does not retain its external inputs; aggregate Slurm limits need not be permanent; compressed caps and client-side symlink exclusions do not establish archive safety; and restoring an older DB requires discovery of remote work absent from that DB.

Current research also adds a patched linked-SQLite requirement, exposes the client Python/TOML mismatch, and requires a more accurate build-versus-buy appendix. The refined plan makes missing local facts explicit enablement gates instead of filling them in.
