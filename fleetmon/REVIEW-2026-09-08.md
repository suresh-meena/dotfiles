# Dashboard and runtime review

This review used repository code, temporary SQLite databases, synthetic fleet
fixtures, and local helper runs. It did not contact fleet hosts or change any
running service.

The dashboard keeps its existing flat style. Fixes cover narrow-screen overflow,
table scrolling, keyboard focus and text selection during refresh, visible sort
direction, active navigation, and chart range changes while a request is pending.
Charts now use the selected time range and retain the requested point budget for
each GPU. Redundant interface notes and repeated GPU model names in chart legends
were removed.

Backend fixes:

- Web query capacity stays occupied until the actual worker finishes, even if
  the request is cancelled. Query failures return 503 instead of empty success.
- A single bounded local worker handles SQLite writes, state-file fsync,
  retention, backups, and health notification delivery without blocking the
  event loop. It finishes running work before SQLite closes.
- Inventory failures retry at the inventory interval. Concurrent readers share
  a locked GPU cache with a monotonic expiry.
- Retention batches both poll and scheduler deletions. Old, unconfirmed job
  records expire even when their last known state was RUNNING. Current scheduler
  reports refresh those records. Retired host metadata can expire too.
- Backups reserve their destination exclusively with mode 0600 and remove an
  incomplete file after failure. Invalid backup configuration is checked before
  opening SQLite. Non-ASCII Basic credentials no longer cause an auth exception.

The compute helper remains a process that collects one snapshot and exits. Its
process inspection, emitted records, username cache and output are capped. The
hub deliberately owns persistent history and operational state; it is not
stateless.

Validation: 244 runtime tests passed, including the JavaScript harness and nine
new backend regression tests. Ruff checks passed for the changed Python files.
The browser check covered all five pages at 320, 390, 768 and 1440 pixels, search
focus and selection across refreshes, table scroll position, and mobile
navigation. No page errors or page-wide horizontal overflow were observed.

A local load check wrote 4,800 snapshots for eight synthetic hosts, with four
GPUs and 80 current processes per host. It performed repeated API reads and
retention, followed by an online backup and restore.

These measurements cover the stated fixtures and machine, not live-fleet load
or an indefinite uptime guarantee. GPU hardware access was not exercised by the
local helper runs.

Installer tests were excluded from the runtime result. A saved pre-change copy
reproduced their existing failure: `env: 'bash\r': No such file or directory`.
The existing CRLF line endings were preserved, as directed by `CONTEXT.md`.
Configuration tests used an executable offline fleetctl stub; polling tests use
their own fake targets and controllers. FastAPI's existing deprecation warnings
remain.

The browser check is retained in `tests/browser_check.py`. With hub/test extras,
Playwright and Chromium installed, run it from the fleetmon directory with
`PYTHONPATH=src python tests/browser_check.py --output-dir /tmp/fleetmon-browser`.
It serves synthetic data through TestClient and intercepts browser requests;
it opens no listener and contacts no fleet target.
